# 国家级根 CA 与区域性综合 CA 机构调研报告

> 调研目的：对照国内真实持证 CA 的通行做法，为院内自研 CA（根 CA 自签 / 证书签发 / CRL 吊销 / 在线校验 / SM2 国密登录，Java + BouncyCastle 实现）提供对标参考。
> 调研范围：仅限**国家级 / 金融级 CA** 与**区域性综合电子认证服务机构**，不涉及商密厂商产品评测、医疗电子签章专项。
> 调研日期：2026-10-27。所有关键结论以 [S#] 标注来源，来源清单见文末，逐条标注【已查证】（政府 / 监管公示 / 官方规范 / 权威媒体）或【厂商自述】（厂商官网 / 白皮书 / CPS）。

|---|---|---|

## 二、代表厂商五维度详析

### 2.1 中金金融认证中心（CFCA）——金融级国家级根 CA

**基本情况**：由中国人民银行于 1998 年牵头组建、全国商业银行联合共建，2000 年正式挂牌，2004 年企业化转制为中国银联控股子公司 [S3][S4]。持有工信部《电子认证服务许可证》[S1]、国密局《电子认证服务使用密码许可证》、《电子政务电子认证服务机构资质》（2025 年获颁新版）[S5][S6]；是国内唯一同时入根微软、Mozilla、谷歌、苹果及 Adobe 五大根信任库的国产 CA，并通过 WebTrust 国际审计 [S7]。官网：https://www.cfca.com.cn 。

**① PKI/CA 架构与证书体系**
- 采用"根 CA → 二级业务 CA → RA"分层架构。CA 承担证书签发、更新、吊销、密钥管理、证书查询、CRL 发布、政策制定 [S8]。
- 通过协议授权合作机构作为 **RA（注册机构）**，由 RA 受理用户申请、审核申请信息、协助申领证书；CFCA 发布有专门的《注册机构运营管理规范》，对 RA 网络、证书密钥的产生 / 存储 / 使用 / 备份 / 恢复 / 销毁全周期作权限管控 [S9][S10]。
- 证书品类覆盖个人 / 机构 / 设备 / 服务器（SSL）/ 代码签名 / 安全电子邮件等；代码签名证书由 CFCA OCA1 或 ACS 二级 CA 签发 [S8]。
- 持有全球信任体系（Global-Trust）独立 CP/CPS 体系 [S11]。

**② 密码算法**
- 国际线：RSA 2048/4096、SHA-256 系列（全球信任 SSL 体系）[S7][S11]。
- 国密线：支持 SM2 / SM3 / SM4，是中国金融 IC 卡规范（PBOC）换芯标准的长期技术支撑单位 [S12]；金融行业国密改造主力 CA。

**③ 密钥管理与硬件**
- 自有 **KMC（密钥管理中心）**产品，承担密钥备份与恢复：当用户忘记存储口令、或存储密钥的智能设备损坏时，KMC 经 CA 转发恢复申请后，从数据库取出密钥并以安全方式发还用户 [S13]。
- Global-Trust CP/CPS 4.10 明确 Key Escrow & Recovery 条款：要求订阅方在密钥疑似泄漏时申请 rekey（重签发），不得私自变更服务器配置 [S11]。
- 根 / 二级根密钥运行于经国家密码主管部门许可的硬件密码模块（HSM / 服务器密码机）；具体型号未公开披露【未查到公开型号】。

**④ 证书生命周期**
- 签发：RA 受理 → 资质审核 → CA 签发 → 写入介质（如电子钥匙 / USBKey）[S14]。
- 更新：支持证书到期前自动 / 主动更新；Global-Trust 体系支持 rekey [S11]。
- 吊销：CA 维护 CRL 并发布；同时提供在线状态查询（CP/CPS 规定）[S8]。
- 归档：CP/CPS 要求签发与撤销记录留存；具体留存年限【未查到公开年限，参考行业惯例见 §3.5】。

**⑤ 行业落地**
- 金融：网上银行、第三方支付、电子票据、电子保单；服务全国绝大部分商业银行 [S4]。
- 政务 / 招投标：国家电网"SG186"工程招投标等供应商电子钥匙（经指定服务商 UTC 受理）[S14]。
- 电子签署 / 司法：云证通移动签名平台、综合司法存证服务 [S15]。
- 集成方式：提供 SDK、签名服务器、时间戳、电子印章接口；对外通过 RA 接入行业机构。

### 2.2 北京数字认证股份有限公司（北京 CA / BJCA）——区域龙头 + 上市公司

**基本情况**：工信部持证（名单序号 3）[S1]；上市公司（数字认证，300579）。持工信部《电子认证服务许可证》、国密局商用密码销售 / 使用许可、电子政务电子认证服务许可 [S16][S17]。官网：https://www.bjca.cn 。

**① PKI/CA 架构与证书体系**
- 自研"数字证书认证系统（CA）"，产品即 **RA + CA 两大核心子系统**，具备《商用密码产品认证证书》，入围国密局信创目录 [S18]。
- 支持**多级 CA 与虚拟 CA**，可灵活适配密码设备；证书品类含个人证书、机构证书、设备证书 [S16]。
- SM2 体系采用国家密码管理局根证书下发：ROOTCA(SM2) 为 SM2 256-bit，下设 Beijing SM2 CA，再签发 EV/OV/IV/DV 级服务器证书 [S19]。

**② 密码算法**
- 双算法并行：支持最新国密 SM2 / SM3 / SM4，同时兼容 RSA 1024 / 2048 [S16]。
- 遵循国密局《SM2 椭圆曲线公钥密码算法》《SM3 密码杂凑算法》《基于 SM2 密码算法的数字证书格式规范》等标准 [S18]。

**③ 密钥管理与硬件**
- CA 产品可对接经认证的密码设备（密码机 / 智能密码钥匙），支持可视化配置；RA/CA 子系统分离部署 [S18]。
- 私钥默认不出介质（USBKey / 智能密码钥匙）；具体 KMC 密钥恢复服务【未查到与 CFCA 同等公开细节】。

**④ 证书生命周期**
- 在线证书申请 / 审核 / 签发 / 更新 / 吊销全流程；为 SSL 客户提供"5 年服务周期内免费升级算法、自动续期"运维 [S17]。
- 对接多家国际 CA 与国密 CA，毫秒级故障切换保障双证书连续供应 [S17]。

**⑤ 行业落地**
- **政务（核心场景）**：承担北京市"互联网+政务服务"三大应用支撑平台；建设覆盖百万级法人用户的**"法人一证通"**平台——企业持一张证书即可登录税务、社保、公积金、工商、统计等 30 多家单位 50 多个业务系统，超 150 万法人用户使用 [S20][S21][S22]。
- 部委：为教育部、卫健委、交通部、财政部、公安部、人社部、外交部、住建部、工信部等提供服务 [S23]。
- 国密改造 / 电子招投标 / 非税电子票据 [S23]。

### 2.3 上海市数字证书认证中心（上海 CA / SHECA）——国资区域 CA

**基本情况**：1998 年在上海市政府支持下成立的国有企业，2022 年成为上海数据集团首批成员企业；国内首批第三方电子认证服务机构 [S24]。持工信部《电子认证服务许可证》[S1]、国密局《电子认证服务使用密码许可证》《电子政务电子认证服务机构》资质 [S25][S26]；通过 WebTrust、CMMI3、ISO9001、ISO27001 [S24]。官网：https://www.sheca.com 。

**① PKI/CA 架构与证书体系**
- 第三方 CA，签发个人 / 机构 / 服务器 / 设备证书；有公开的 EV 证书策略（CP）文档，明确证书层次架构 [S27]。
- 采用"根 CA → 中级 CA → 订阅者"分层，不随意签发外部中级 CA（参考其 EV CP 对层次的约束做法）[S27]。

**② 密码算法**
- 国际线：RSA / SHA 体系（WebTrust、全球信任 SSL）。
- 国密线：作为上海商密骨干企业，全面支持 SM2 / SM3 / SM4 国密改造 [S28]。

**③ 密钥管理与硬件**
- 私钥生成与保护使用**经国家密码主管部门批准和许可的密码模块（硬件密码模块）**，并遵循 GM/T 15135、ISO 19790 或 FIPS 140-2 Level 3 要求 [S27]。
- 2026 年 3 月发布自研**"芯密服务器密码机 UniTrust NHSM"**，为国内首款"内生密码"架构通过商用密码产品认证的安全二级服务器密码机 [S29]——体现区域 CA 自研 HSM 的趋势。

**④ 证书生命周期**
- EV CP 中规定密码模块访问控制、订阅者身份核验、证书撤销与状态发布；CRL / OCSP 为标准配置 [S27]。
- 具体留存年限【未查到公开年限】。

**⑤ 行业落地**
- 上海政务"一网通办"、企业一证通、电子招投标、医疗 / 金融集成；作为上海市属商密骨干参展上交会商密展 [S28]。
- 集成方式：提供证书服务 API、签名中间件、时间戳服务。

## 三、该类 CA 的共性体系（对院内自研 CA 的直接对标点）

### 3.1 分层架构：根 CA — 二级 CA — RA

真实持证 CA 普遍采用**离线根 + 在线二级 CA + 分布 RA**结构：

- **根 CA（自签根证书）**：离线 / 机房物理隔离，仅用于签发下级 CA 证书，生命周期长达 10–20 年；
- **二级 CA（业务 CA）**：在线运行，直接面向用户签发终端证书；
- **RA（注册机构）**：不握签发密钥，只做身份受理与审核，可分布在合作银行 / 政务大厅 / 行业机构（如 CFCA 通过授权 RA 覆盖全国 [S9]；北京 CA 产品即 RA + CA 两子系统分离 [S18]）。

> 院内对标：自研"根 CA 自签"对应离线根；建议把"审核（RA）"与"签发（CA）"在逻辑上分离，即使物理同一进程，也应按权限与流程区分。

### 3.2 双证书体系（签名证书 + 加密证书）——国密特色

这是中国 SM2 体系区别于国际单证书体系的**核心特征**，依据 GM/T 0034-2014 [S44][S45]：

| 证书 | 私钥生成方 | CA 是否备份 | 用途 | 丢失后 |
|---|---|---|---|---|
| **签名证书** | 用户本人（在 USBKey / 终端生成） | **不备份、不可恢复** | 身份认证、电子签名、不可否认 | 立即吊销 → 重新申请新证 [S46] |
| **加密证书** | **KMC（密钥管理中心）生成并托管** | **备份、可恢复** | 数据加密 / 解密 | 经审批从 KMC 恢复 [S44][S46] |

- 加密私钥由 KMC 生成后，用**用户的签名公钥做数字信封**（SM2 数字信封）安全下发给用户，用户无 KMC 授权无法导出托管密钥 [S44][S45]。
- CFCA 的 KMC 产品即实现此机制：用户忘记口令 / 介质损坏时，经 CA 转发恢复申请，KMC 取出密钥安全发还 [S13]。
- IETF 已出现 ACME for SM2 Dual-Certificate 扩展草案，说明该模式正被国际标准化关注 [S44]。

> 院内对标：若登录只做"身份认证 / 签名"，单签名证书即可；若将来要做"加密传输 / 数据加密存储 / 历史数据解密"，则必须配套 KMC 加密密钥托管。HIS 场景以身份认证 + 签名为主，可先做签名证书，但架构上预留加密证书扩展位。

### 3.3 密钥管理硬件（HSM / 服务器密码机 / 智能密码钥匙）

- **根 / 二级根密钥**：必须运行于经国家密码主管部门认证的硬件密码模块（服务器密码机 / HSM），满足 GM/T 15135 或 FIPS 140-2 Level 3 [S27]。区域 CA 趋势是自研 HSM（如上海 CA UniTrust NHSM [S29]）。
- **用户私钥介质**：以**智能密码钥匙（USBKey）**为主，依据 GM/T 0027-2014《智能密码钥匙技术规范》——内置安全芯片、**私钥不出介质**、硬件 + PIN 双因子认证 [S47]。主流厂商：握奇 WatchKey、飞天诚信、海泰方圆、华大智宝等，产品过 EAL4+ [S48]。

> 院内对标：纯软件（BouncyCastle）实现无法满足"私钥不出介质 / 密钥不出 HSM"的监管要求；院内 CA 若仅用于院内登录且不对外发证，软件根可接受，但根私钥应离线保管、加口令保护，且审计留痕。

### 3.4 证书生命周期与吊销（CRL / OCSP）

- **签发**：RA 受理 → 身份核验（机构资质 / 法人授权 / 经办人实名）→ CA 签发 → 写入介质 [S9][S35]。
- **更新**：到期前主动 / 自动续期；支持算法升级（如 RSA→SM2）。
- **吊销（CRL）**：证书吊销列表，由 CA 定期签名发布；如四川 CA 业务规则要求 CRL 备份间隔不超过 24 小时、**备份保存不少于证书失效后 10 年** [S49]。
- **在线校验（OCSP）**：依据 RFC 2560，实时返回 good / revoked / unknown 三态；CA 须在证书 Authority Info Access 扩展中给出 OCSP Responder 地址，服务 7×24 可用 [S49][S50]。
- **归档**：签发与撤销记录长期保存（行业惯例 ≥ 证书失效后 5–10 年），用于事后举证（电子签名可追溯）。

> 院内对标：自研已有 CRL + 在线校验，方向正确；建议补三点：① 在证书里写 `cRLDistributionPoints` 与 `authorityInfoAccess`（OCSP）扩展，否则客户端无法自动发现吊销地址；② CRL / OCSP 响应要签名并带 thisUpdate / nextUpdate；③ 建立证书与签发记录的归档表。

### 3.5 证书应用场景

- **政务**：法人一证通（北京 [S20]、上海、浙江）、一网通办、电子招投标、电子票据；
- **金融**：网银、支付、电子保单、票据（CFCA [S4]）；
- **口岸 / 监管**：电子口岸 IC 卡（海关 [S42]）；
- **企业**：SSL / HTTPS、代码签名、PDF 文档签名、电子印章、VPN / 设备认证。

## 五、对院内自研 CA 的对标结论（要点）

1. **架构**：真实 CA = 离线根 + 在线二级 CA + RA 审核分离。院内软件根可先单级，但应把"审核"与"签发"逻辑分离、根私钥离线加密保管。
2. **双证书**：HIS 登录以身份认证 / 电子签名为主，**先做签名证书**（私钥客户端生成、CA 不备份）；预留加密证书 + KMC 扩展，将来做数据加密 / 历史解密时再建托管。
3. **算法**：SM2 / SM3 / SM4 已成为区域 CA 标配（浙江 [S39]、北京 [S16]、GDCA [S34] 均全支持），院内选 SM2 方向正确；建议同时兼容 RSA 以便对接既有系统。
4. **吊销**：补全证书扩展（CDP / AIA-OCSP），CRL 定期签名发布、OCSP 三态响应，建立签发 / 吊销记录归档（≥ 证书失效后 5–10 年 [S49]）。
5. **介质差距**：真实 CA 用户私钥在 USBKey / HSM 内不可导出 [S47][S27]；院内纯软件 BC 实现达不到对外发证监管要求，仅适合院内闭环——若将来要对外提供电子签名法律效力，必须升级硬件密码设备并申请相应资质。
6. **资质红线**：面向社会公众发证须持工信部《电子认证服务许可证》+ 国密局使用密码许可证 [S1][S5]；院内自用不触红线，但不可对外商用发证。

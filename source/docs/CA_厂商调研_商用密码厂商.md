# 商用密码/信息安全厂商 CA·PKI 产品调研报告

> **调研目的**：对照国内真实商密/PKI 厂商做法，评估自研院内 CA 系统（根 CA 自签、证书签发、CRL 吊销、在线校验、SM2 国密登录、Java/BouncyCastle 实现、私钥文件落盘）的设计差距。
> **调研范围**：商用密码/信息安全厂商中做 CA/PKI 产品与密码设备的厂商。
> **调研时间**：2026-10-27。
> **标注约定**：正文关键结论以 [n] 引用文末来源；来源逐条标注【已查证】（政府/交易所公告、上市公司年报、权威媒体、央企官网）或【厂商自述】（厂商官网/产品页/新闻稿）。查不到权威来源的条目明确写明"未查到权威来源"。

## 二、代表厂商五维度详析（5 家）

### 2.1 三未信安（SZT1701 / SecCert-CA 数字证书认证系统）

来源：[3][25][26][27]

**① PKI/CA 架构与证书体系**
- 产品形态为 2U 硬件一体机，证书容量百万级（宣传支持 100 万–1000 万证书管理）[25]。
- 支持 X.509 V3 证书格式；人员管理采用三级管理模式、严格权限控制 [25]。
- 第三方服务（LDAP 目录、OCSP、密钥管理中心 KMC）可裁剪——可使用自有或第三方 OCSP 与 KMC，支持标准 LDAP 协议将证书/CRL 实时发布到目录服务器 [25]。
- 服务接口协议：CPMv2、REST [25]。

**② 密码算法**
- 同时支持 **SM2、RSA、ECDSA**；产品采用国密指定算法 SM1/SM2/SM3/SM4 [25]。
- 公司层面全面支持 SM1/SM2/SM3/SM4/SM7/SM9/ZUC 及国际算法、抗量子算法 [26][27]（年报口径）。

**③ 密钥管理与硬件**
- CA 根密钥及系统密钥由**自研服务器密码机生成、管理**，支持符合《密码设备应用接口规范》(GM/T 0018) 的硬件密码设备 [25]。
- 配套密码产品线：服务器密码机 [28]、云服务器密码机（VSM 虚拟化）[29]、金融数据密码机、签名验签服务器；近 200 款产品取得国家商用密码产品认证证书 [26]。
- 具备密钥恢复能力（见 ④）。

**④ 证书生命周期**
- 覆盖申请、发布、下载、注销、更新、**冻结/解冻、延期、密钥恢复**；支持按用途/类型设定证书模板 [25]。
- CRL 管理、安全审计、备份归档、日志管理 [25]。

**⑤ 行业落地**
- 产品面向电子商务、电子政务及企业信息化 [25]；密码设备已用于网上审批、网上办公、网上银行、网上证券等 [28]。
- 上市主体 688489，2008 年成立，总部北京 [1][2]。

### 2.2 吉大正元（电子证书认证系统 / 一体化 CA）

来源：[5][30][31][32]

**① PKI/CA 架构与证书体系**
- 产品族完整：电子证书认证系统（CA）、**一体化 CA 系统**（硬件一体化 CA）、证书注册中心受理点系统（RA）、目录服务器（银河目录）、证书自助服务系统 [5]。
- RA 受理点支持"挂接密钥管理中心（KM）管理用户加密密钥，提高加密密钥安全性和**可恢复性**"；支持证书模板灵活签发多类型证书 [5]。
- 另有协同签名系统（MCS）配合 RA 为移动终端签发证书 [5]。

**② 密码算法**
- 智能密码钥匙内置 **SSF33、SM1、SM2、SM3、SM4** 国产算法 [32]。
- 终端安全密码模块同时支持 RSA 与 SM2/SM3/SM4 [5]；区块链方案采用 SM2/SM3/SM4 [31]。

**③ 密钥管理与硬件**
- 密钥管理系统：支持对称与非对称密钥全生命周期管理、司法取证，基于国产化硬件、内嵌 CA 能力、标配双机热备 [30]。
- 硬件：服务器密码机、云服务器密码机（密钥管理与设备管理分离）、金融数据密码机、数字签名服务器、时间戳服务器 [5]。
- USBKey 符合国密局"**密钥不落地**"技术规范 [32]。

**④ 证书生命周期**
- 证书申请、审核、签发、注销、更新、查询综合管理 [5]；证书综合查询系统做统计/事件追踪 [5]。
- V2X-PKI 提供注册/身份/假名/应用证书签发及**证书注销列表（CRL）签发**服务 [5]。

**⑤ 行业落地**
- 国内主要 PKI 产品供应商 [33]；落地等级保护/分级保护解决方案（以 PKI/KMI 为信任基础设施）[5]；车联网 V2X-PKI、电子政务、区块链 [5][31]。
- 股票代码 003029 [4]。

### 2.3 电科网安 / 卫士通（数字证书认证系统）

来源：[8][9][34][35][6][7]

**① PKI/CA 架构与证书体系**
- 满足国密局商密办《数字证书认证系统建设规范》[8]。
- 典型部署为**三区分离**（厂商公开架构图）：
  - **核心区**：证书签发系统、工作 CA 数据库、非对称密钥管理系统、KMC 数据库、密码机；
  - **管理区**：注册审核系统、RA 数据库、注册验证终端、审核/管理终端、密码机；
  - **服务区**：证书状态查询系统、证书目录服务（主/从）、密码机；
  - **根证书签发系统：离线部署**（物理隔离），经核心区防火墙对接 [8]。
- RA 注册审核界面支持"双证书 / 签名证书 / 加密证书"单选项、证书算法选择（SM2）、CRL 发布点扩展项配置 [8]。

**② 密码算法**
- 服务器密码机支持 **SM1/SM2/SM3/SM4/SM9 及 ZUC** 国密算法 [35]。

**③ 密钥管理与硬件**
- 密钥产生、分发由系统完成；核心区设"非对称密钥管理系统 + KMC 数据库 + 密码机" [8]。
- 密码产品：服务器密码机、金融数据密码机（过国家主管部门鉴定）、商用 PCI-E 密码卡、云服务器密码机（VSM 隔离）[9][35][36]。
- 移动终端密码软卡依托第三方 CA 提供证书签发/更新/吊销 [37]。

**④ 证书生命周期**
- 证书制作、签发发布、管理、查询下载、验证、密钥管理、管理员管理、**日志审计归档** [8]。

**⑤ 行业落地**
- 国内首批商密产品研发/生产/销售资质、首批涉密集成甲级 [9]；中国电科（CETC）/中国网安（CCSC）旗下网络安全上市平台 [6][7]。
- 控股股东原为中电科第三十研究所，2015 年股权无偿划转至中国网安 [34]。

### 2.4 格尔软件（根证书签发系统 / 数字证书认证系统）

来源：[12][13][38][10]

**① PKI/CA 架构与证书体系**
- 完整 PKI 子系统：**CA + RA + LDAP 目录 + OCSP 在线查询 + 时间戳（TSA）** [12]。
- 按容量分三档：企业版（≤1 万张）、大客户版（1–50 万张）、运营中心版（≥500 万张，面向区域 CA/运营 CA）[12]。
- 支持 **CA 树状信任模式、分级 CA 管理、多级扩展认证**；大客户版提供证书策略管理、CRL 策略、证书模板、RA 管理 [12]。
- 支持接入第三方 KM/CA/RA [12]。

**② 密码算法**
- **同时支持 SM2/SM3/SM4 与 RSA（RSA1024/RSA2048）**，支持 SM3WITHSM2 证书签发；支持 SM1/SSF33 密钥不落地机制 [12]。
- 国内首批通过国密局审查、支持 SM2 算法的 PKI 厂商（2009 年通过安审/鉴定，获 SZT0901、SYT0901、SRT0903 资质）[12][13]。

**③ 密钥管理与硬件**
- 企业版 CA 内置密钥管理模块；支持"内嵌简易用户密钥管理模块做无 KM 测试"，生产可外接 KM [12]。
- 管理安全：MofN 安全登录、**管理与审计相互独立的二线三层权限体系**、双人制管理 [12]。
- 跨平台兼容 SJY42C、SHJ0901-B、SJJ1012、SJJ1115、SJL22 等多种加密机 [12]。
- 自有硬件：服务器密码机、云服务器密码机（密码模块）、签名验签服务器 [13]。

**④ 证书生命周期**
- 注册/签发/更新/恢复/废除/重发；**分块 CRL 与增量 CRL 发布、基于 HTTP 的 CRL 发布** [12]。
- 批量注册、批量审核、批量签发、批量废除；系统备份/恢复、在线升级、SYSLOG 外发日志 [12]。

**⑤ 行业落地**
- 参与我国第三方数字认证中心系统建设 20 多个，2 次获国家科技进步二等奖 [13]。
- 可平滑升级国产化（国产芯片/OS/数据库/中间件，达梦、金仓、南大等）[12]；2017 年上交所主板上市（603232）[10][11]。

### 2.5 数字认证 BJCA（数字证书认证系统 CA）

来源：[16][17][14][15]

**① PKI/CA 架构与证书体系**
- 产品主要包括 **RA、CA 两大核心子系统** [16]。
- 证书类型丰富：个人、机构、设备、微软域证书、代码签名、车联网证书 [16]。
- 自身即运营级 CA（原北京数字认证中心），按"电信级 CA"经验开发 [39]。

**② 密码算法**
- 遵循《SM2 椭圆曲线公钥密码算法》《SM3 密码杂凑算法》《基于 SM2 密码算法的数字证书格式规范》等国密标准 [16]。
- 具备《商用密码产品认证证书》，入围国密局信创目录 [16]。

**③ 密钥管理与硬件**
- 配套密钥管理系统（KMS）、密码服务管理平台 [17]。
- 加密场景：签发**加密证书（加密密钥）**，私钥经 USBKey 安全存储，支持数字信封 [16]。
- 国产化适配：麒麟、统信 OS、国产中间件/数据库/硬件密码设备 [16]。

**④ 证书生命周期**
- 证书签发、更新、吊销、CRL 下载、证书链下载 [16]。
- 对外集成接口：证书申请/更新/补办/注销/下载/状态查询；支持 **HTTPS、SCEP、MQTT、CMP** 多种标准协议 [16]。
- 双因子认证场景**明确标注"符合国家三级等保和密评要求"** [16]。

**⑤ 行业落地**
- 政务（非税电子票据、电子招投标、国密 HTTPS）、车联网 V2X [16][17]。
- 北京市国有资产经营公司控股的国有企业，持电子认证服务许可证、电子政务电子认证服务许可、卫生系统电子认证服务资质 [14]；创业板 300579 [15]。

## 四、对自研院内 CA 的对标要点小结

> 以下为基于上述厂商公开做法的归纳，供设计评估参考；每条均可回溯到第二、三章来源。

| 维度 | 厂商通行做法 | 自研现状对照 |
|---|---|---|
| 根 CA 安全 | 根证书签发系统**离线/物理隔离部署**，工作 CA 在线（卫士通典型架构）[8] | 自研为根 CA 自签在线运行——建议评估根 CA 离线化 |
| 密钥存储 | CA 根密钥由**服务器密码机/HSM 生成并存储**；USBKey/介质"密钥不落地"（三未、吉大、格尔）[25][32][12] | **私钥文件落盘**——与厂商"私钥不出密码机"差距最大，是密评/等保高风险点 |
| 双证书体系 | 普遍支持签名证书 + 加密证书；加密密钥由 **KMC 托管且可恢复**（三未"密钥恢复"、吉大 KM、卫士通 KMC）[25][5][8] | 自研仅 SM2 登录双证书场景需确认是否区分签名/加密证书及加密密钥托管 |
| 证书生命周期 | 签发/更新/冻结解冻/延期/吊销/CRL + OCSP 双通道（格尔增量/分块 CRL、HTTP CRL；数字认证 CRL+状态查询）[12][16] | 自研有 CRL 吊销 + 在线校验，建议补齐冻结/解冻、CRL 增量发布、归档审计 |
| 权限与审计 | 管理/审核/审计三权分立、双人制、MofN、日志审计归档（格尔二线三层、卫士通日志审计归档）[12][8] | 需对照三级等保要求核查三权分立与审计完整性 |
| 合规适配 | 数字认证明确"符合三级等保和密评"；产品需《商用密码产品认证证书》[16][25] | 院内自研系统不强制商密产品认证，但密评对密钥存储/根 CA 隔离的要求一致 |
| 集成接口 | SCEP/CMP/MQTT/HTTPS、SDK（数字认证、吉大 MCTK）[16][5] | 自研 Java/BC 接口需评估是否符合国密标准接口（GM/T 系列）以便对接 |

## 0. 一页速览

| 维度 | 行业现状结论 |
|---|---|
| 法规底座 | 《电子签名法》第十三条"可靠电子签名"四条件 + 第十七条电子认证服务许可（工信部发证）[S1][S2]；WS/T 847—2024 已把医疗电子文档签名算法**强制锁定为 SM2/SM3**[S5] |
| 供给格局 | 三类玩家：①持牌第三方CA（数字认证BJCA、上海CA、深圳CA、苏州CA、国富安、CFCA等）；②签章中间件/组件商（金格iSignature、医信签等）；③HIS/EMR厂商自带集成（卫宁健康CIS内置CA认证与电子签名，对接外部CA）[S6][S12][S16][S18][S23] |
| 卫生行业CA | 国家卫健委（原卫生部）2010年建成"卫生部数字证书服务管理平台 + 省级遴选CA机构"两级体系，要求互信互认、一证多用；CA机构须持工信部《电子认证服务许可证》[S3] |
| 医保方向 | 医保电子凭证由国家医保信息平台统一生成（SM4加密+SM3签名产生64位标识码），接口强制 SM2/SM3 签名 + SM4 加密、双向验签；第三方渠道（微信/支付宝）须国家局备案分配 APPID/密钥并通过安全测评 [S9][S10] |
| 硬件形态 | 传统 USBKey/智能密码钥匙仍是合规介质；移动趋势是"手机APP移动CA证书"替代USBKey，且 WS/T 847—2024 明确移动私钥**不得集中托管服务端**，须密钥分割、介质+服务端联合签名 [S5] |

### 1.2 医院电子签名的典型形态（行业通行做法）

- **医护数字证书 + USBKey/智能密码钥匙**：医生登录与书写签名时插入介质，PIN码/生物识别解锁，私钥不出介质。WS/T 847—2024 要求介质中"签名私钥不能以任何形式获取或从介质中导出"，并须采用生物识别、PIN码、设备指纹之一或组合确保持有人专有控制 [S5]。
- **移动签名替代USBKey**：上海CA胸科/瑞金医院案例显示，医护通过手机APP移动数字证书完成PC扫码签名或移动端签名，免物理介质 [S12][S13]；WS/T 847—2024 对移动形态的硬性约束是：私钥不得集中托管在服务端，须采用密钥分割技术，由私钥存储介质与签名服务端共同完成签名 [S5]。
- **时间戳**：电子病历应用管理规范要求"采用权威可靠时间源"[S4]；WS/T 847—2024 要求签名与时间戳同时执行、一一对应；CFCA方案采用国家授时中心时间源 [S4][S5][S21]。
- **患者（服务对象）签名**：知情同意类文书采用"事件型数字证书"——两种以上组合鉴别（身份证识别/指纹/人脸/短信），事件型证书固化签署事件信息，私钥仅用于当次签署、计算后立即销毁 [S5]；金格方案以"数字笔迹"表达患者签署意愿 [S22]。
- **电子病历归档签名**：归档前先验签已有签名有效性，验证通过后由医疗机构（单位）证书对归档文档再签一次并打时间戳；复制、封存（医患双方分别签名）、共享（发送前验签+发送时签名、接收方再验签）均有标准动作 [S5]。

## 2. B线：卫生行业CA体系

### 2.1 国家体系框架（原卫生部两级机制）

依据《卫生部办公厅关于做好卫生系统电子认证服务体系建设工作的通知》（卫办综发〔2010〕74号）[S3]：

| 机制要点 | 原文要点 |
|---|---|
| 体系目标 | 数字证书能在各类卫生信息系统中注册、授权及使用，实现**互信互认、一证多用** |
| 两级遴选 | 部机关及直属单位CA机构由卫生部**公开招标确定**；各省级卫生行政部门按《卫生系统电子认证服务管理办法》**自主选择本辖区CA机构**并报卫生部 |
| CA机构准入 | 须持工信部《电子认证服务许可证》、提交国有资产控股证明、省级卫生部门评估、卫生部接入测试（测电子认证系统/证书介质/证书格式/证书应用接口）后接入"卫生部数字证书服务管理平台"，并在卫生部网站公布名单 |
| 服务内容 | 证书签证、发放、更新、吊销、解锁、培训 |
| 配套规范 | 《卫生系统电子认证服务规范（试行）》《卫生系统数字证书应用集成规范（试行）》《卫生系统数字证书格式规范（试行）》《卫生系统数字证书介质技术规范（试行）》《卫生系统数字证书服务管理平台接入规范（试行）》 |

> 注：WS/T 847—2024 规范性引用文件中仍引用《卫生系统电子认证服务管理办法（试行）》（卫办发〔2009〕125号）及上述2010年格式/介质/集成规范，说明该体系文件至今仍是行业标准的上位依据 [S5]。

### 2.2 落地形态

- **省级/市级实体体系**：上海CA为上海市卫健委搭建市级电子认证体系，覆盖委属及托管医疗机构，并"整合《医师联网注册及考核管理系统》"建设市级证书管理系统——即以医师执业注册库作为RA身份核验底座的真实做法 [S14]。
- **移动端发证**：新疆CA"医网信"APP支持医护在线购买证书、绑定设备使用 [S28]；医信签的移动CA证书即由"具有卫生资质的CA机构签发"，对应上述遴选体系 [S23]。
- **配套制度**：医疗机构、医师、护士电子证照已全国推行，与现行证照并行、具有同等效力，由机构端/个人端在电子化注册系统申领 [S32]。

## 3. C线：医保方向

### 3.1 医保电子凭证的密码/认证体系（XJ-D01-2019）

依据国家医保局网信办《医疗保障信息平台电子凭证技术规范》（XJ-D01-2019，广东省医保局公开PDF）[S9]：

| 要点 | 规范原文要点 |
|---|---|
| 凭证生成 | 医保电子凭证由国家医保信息平台**统一生成**，一人一码；基于证件类型、证件号码、姓名等基础信息，**采用SM4加密算法和SM3签名产生的64位标识码**；是办理医保线上业务的唯一身份凭证 |
| 激活 | 须激活后使用，每个凭证仅激活一次；操作者须完成**实人认证**并成功设置密码后方可激活 |
| 部署 | 电子凭证管理中心国家集中部署；电子凭证业务中台国家、省级两级部署；二维码由发码方负责解码，跨省通过国家平台交换数据 |
| 安全设计原则 | 通信加密机制 + 令牌校验机制 + 二维码自动/手动刷新机制 + 码值业务经办**一次有效**机制 |
| 结算鉴权 | 扫码结算时，省级业务中台解析验证二维码后返回人员基础信息与**鉴权TOKEN**，医保核心系统再对TOKEN验签通过后方可结算 |
| 接口安全 | HTTPS传输、POST、JSON、UTF-8；**签名算法SM2/SM3，加密算法SM2/SM4；请求和接收数据均需校验签名**；公共参数含 orgId、encType、signType、signData、timestamp |
| 受理端接入 | 两定机构（医院HIS/药店）可按地方选择 **https接口服务** 或 **dll动态库**（NationECCode.dll，国家局统一提供下发）接入；终端须注册并获20位全国唯一终端备案号 |
| 第三方渠道 | 微信/支付宝等第三方渠道须向地方医保申请、国家局审批授权；国家局为每个渠道分配渠道编号、应用编号（APPID）、应用密码（SECRET）和数字密钥；**入网须通过技术标准验证和安全测评**；渠道须确保用户为实人操作，否则担责 |

### 3.2 医保移动支付与"一码付"安全

- 国家医保局官方表述："一码付"采用**人脸识别、实名认证及实人验证三重核验机制**；医保综合服务终端遵循国家局技术规范，网络使用**医保专网**，确保个人信息与基金安全 [S33]。
- 规模数据：截至2023年11月医保码全国用户超10亿，合作渠道含支付宝、微信等互联网平台及银行渠道共234个 [S34]；截至2025年7月医保码接入定点医药机构超93万家 [S10]。
- 国家标准：2025年8月，全国首项医疗保障领域国家标准发布，统一规定**医保码（医保电子凭证）、医保移动支付、医保电子处方、个人医保信息授权查询**的接入方式、功能要求、性能要求与安全要求 [S10]。配套技术规范要求"根据SM2算法签名报文管理数据、鉴别信息，实现敏感信息、业务数据传输完整性保护" [S11]。

### 3.3 医保结算/处方接口的签名验签（省级接入规范共性）

云南、广西医保局公开的《医保电子处方中心定点医药机构接入规范》要点一致 [S35][S36]：

| 项 | 规定 |
|---|---|
| 传输/编码 | HTTP/HTTPS；JSON；UTF-8 |
| 签名算法 | 国密 SM2（SM3withSM2） |
| 加密算法 | 国密 SM4 |
| 签名要求 | 请求和接收数据均需校验签名 |
| 判断逻辑 | 优先级：先判断协议字段返回 → 再判断业务返回 → 再判断交易状态 |

## 4. 代表方案五维对比（5个方案）

### 4.1 代表方案①：数字认证（BJCA）医疗电子签名整体方案 [S6][S7][S8]

| 维度 | 描述 |
|---|---|
| ① PKI/CA架构与证书体系 | 持牌CA自签体系，面向医院发放医护人员证书、机构证书；方案覆盖"医技护强身份认证—业务环节签名—患者手写签名—移动终端CA—电子病案可信归档"全链条；自述服务超五成通过电子病历五级评价的医疗机构（对应电子病历分级评价09.02.5/09.02.6条款对可靠电子签名的要求） |
| ② 密码算法 | 官网称"以国产密码算法为核心"建设密码基础设施；产品线按国密体系布局（签名验签服务器、时间戳服务器、电子签章系统）。具体算法矩阵页面未逐项公开，未查到其医疗方案单独的RSA/SM2对照表【厂商自述，未获第三方佐证】 |
| ③ 密钥管理与硬件 | 传统形态为USBKey；同时提供"云签名/移动电子签名"形态；时间戳服务器为独立产品。移动签名的私钥托管细节未公开，按WS/T 847—2024合规要求应采用密钥分割模式 |
| ④ 证书生命周期 | 作为持牌CA提供证书签证、更新、吊销、解锁服务；病案侧覆盖归档、存储、打印、借阅、封存"收管存用"全生命周期，无纸化程度自述达90% |
| ⑤ 行业落地 | 与医院业务系统集成实现全流程无纸化；电子病案归档融合OFD版式；服务对象为各级医疗机构 |

### 4.2 代表方案②：金格科技 iSignature 电子签章（版式文档签章中间件）[S22][S24][S25]

| 维度 | 描述 |
|---|---|
| ① PKI/CA架构与证书体系 | 金格本身是签章中间件/组件商而非CA：负责文档级签章、手写签名、印章管理，数字证书由对接的第三方CA（含卫生资质CA）签发；医疗线覆盖医护技签署、患者签署、病案归档三类对象 |
| ② 密码算法 | OFD API后台签章演示环境钥匙盘序列号即 `sm2kinggrid001`，显示其后端签章基于SM2国密钥匙盘；中间件兼容IE/Chrome/360/搜狗及移动/PC端 |
| ③ 密钥管理与硬件 | 支持钥匙盘（USBKey）签章与服务端后台批量签章；提供云端SaaS（信签电子合同平台，含实名认证、电子签署、印章管理、合同管理）与API/私有云部署 |
| ④ 证书生命周期 | 证书生命周期由对接CA负责；金格侧管理印章生命周期（印章申请、授权、用印留痕） |
| ⑤ 行业落地 | 以文档中间件形态嵌入HIS/电子病历系统（iWebOffice实现病历在线编辑、与HIS集成）；患者侧以数字笔迹表达签署意愿；符合《电子签名法》要求、支持OFD版式归档 |

### 4.3 代表方案③：国家医保电子凭证体系 [S9][S10][S11][S33]

| 维度 | 描述 |
|---|---|
| ① PKI/CA架构与证书体系 | 不采用传统双证书PKI，而是国家医保信息平台集中生成的"医保电子凭证"（64位标识码）作为参保人唯一身份标识；业务中台国家/省级两级部署；机构侧以机构ID（定点医药机构编码）、20位终端备案号标识；第三方渠道（微信/支付宝/银行）经国家局备案后获渠道编号/APPID/SECRET/数字密钥 |

## 6. 对照自研院内CA的要点提示（供评估参考）

1. **算法基线**：院内CA若用于新发/电子病历签名，按 WS/T 847—2024 必须 SM2/SM3（摘要SM3），加密场景 SM4；RSA体系仅应作为兼容存量介质的过渡，而非目标架构 [S5]。
2. **私钥托管红线**：WS/T 847—2024 明确签名私钥不得集中托管服务端；移动签名须密钥分割、介质+服务端联合签名——院内"软证书/服务端代管私钥"模式与现行行业标准冲突 [S5]。
3. **吊销校验**：签名前必须校验证书有效期+颁发者证书链+吊销列表（CRL/OCSP）；标准未强制OCSP协议形态，但必须有吊销查询通道 [S5]。
4. **RA身份核验**：行业通行做法是对接医师/护士执业注册库做身份核验（上海CA整合医师联网注册系统）；院内自签CA的"医护身份真实性"若无外部执业库背书，法律证据力弱于持牌CA证书 [S14]。
5. **医保对接边界**：医保电子凭证体系是国家平台集中签发+国密接口强制双向验签，院内CA不发"医保凭证"，医保结算前置须按省级接入规范做 SM2/SM3 签名 + SM4 加密，且终端备案、渠道备案不可缺 [S9][S35]。
6. **时间戳与归档签名**：权威时间源+签名同时打戳、归档时机构证书再签一次——这是医院无纸化验收（电子病历分级评价）的硬性检查点 [S4][S5][S7]。

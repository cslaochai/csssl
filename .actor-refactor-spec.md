# csssl「业务表禁止存登录账号」改造 — 已完成部分与调用口径（临时交接文件，改完即删）

红线（用户原话）：**严禁在系统里面的业务表存 username，因为这个是账号！账号不能泄密！**
延伸：审计 detail 文案、消息正文、接口出参、前端界面一律不得出现登录账号；姓名只在**写入时**从登录态取快照落库，
读的时候直接读列。**禁止写「按账号回查 ssl_sys_user 拿真实姓名」的任何代码**（`com.csssl.util.ActorNames` 已被删除，
它被用户点名是垃圾代码）。

## 一、实体层（`com.csssl.entity`，已改完，不要再改）

`AuditColumns`（抽象基类）提供 6 个审计字段，除 `AuditLog` 外所有业务实体已 `extends AuditColumns`：
`createdByUserId(Long)` / `createdByName(String)` / `createdAt` / `updatedByUserId(Long)` / `updatedByName(String)` / `updatedAt`。
由 `com.csssl.config.AuditMetaObjectHandler` 在 insert/update 时自动填，**业务代码不要再手工 `setCreatedAt(...)`**；
无登录态时 handler 落 `user_id=NULL` + 姓名常量「系统」（`AuditMetaObjectHandler.SYSTEM_NAME`）。

人员字段改名（String 账号 → Long 用户ID）：

| 实体 | 旧 | 新 |
|---|---|---|
| CertApplication | appliedBy / reviewedBy / assigneeUsername | appliedByUserId / reviewedByUserId / assigneeUserId |
| CaCertOpTicket | requestedBy / reviewedBy / assigneeUsername | requestedByUserId / reviewedByUserId / assigneeUserId |
| CompanyOpTicket | requestedBy / reviewedBy / assigneeUsername | requestedByUserId / reviewedByUserId / assigneeUserId |
| CompanyOpTicket | newHolders（账号CSV）/ voterUsernames（账号CSV） | newHolderUserIds(idCSV) + newHolderNames(姓名CSV) / voterUserIds(idCSV) + voterNames(姓名CSV)，两组同序 |
| CompanyOpVote | voterUsername | voterUserId |
| ApplicationTrail | operatorUsername | operatorUserId |
| Message | recipientUsername / senderUsername | recipientUserId / senderUserId |
| CompanyKeyShare | holderUsername | holderUserId |
| CaSubCaTicket | requestedBy | requestedByUserId |
| CaSubCaApproval | approverUsername | approverUserId |
| CaCert | createdBy | 删了，用基类 createdByName（不要手工 set） |
| ApiClient | createdBy | 删了，用基类 createdByName |
| AuditLog | username | userId（Long）；另新增 signVer(Integer) |
| SysUser | companyUscc | **删了** |

姓名列不变：appliedByName / reviewedByName / assigneeRealName / requestedByName / operatorRealName /
recipientRealName / senderRealName / holderRealName / approverRealName / voterRealName / createdByName / updatedByName。

`LoginUser`（`SecurityContextHolder` 里的身份载体）字段：`userId(Long)` / `username` / `realName` / `roleCode` /
`builtin` / `permissions`；**已没有 companyUscc**。构造器 6 参：
`new LoginUser(userId, username, realName, roleCode, builtin, permCodes)`。
取当前登录人只用 `UserUtils.getLoginUser()` / `UserUtils.requireLoginUser()`。

## 三、改造要求

1. 查询条件、比较、过滤、`LambdaQueryWrapper` 的方法引用与裸列名字符串，全部从账号改成 `user_id`
   （裸列名：`assignee_username`→`assignee_user_id`、`operator_username`→`operator_user_id` 等）。
2. 需要「按账号找人」的地方改成「按 user_id 找人」；需要把一批账号转 id 的地方，改完应不再需要转换
   （上游给的就是 id）。**不许**留 `selectByUsername` 之类的兜底。
3. 单据归属校验口径不变：`当前登录人 userId == 单据 assigneeUserId`；
   提交人≠审批人 用 `Objects.equals(actor.getUserId(), app.getAppliedByUserId())` 之类判断。
4. 未指派/处理人已停用的兜底 SQL 用 id 域，例如
   `assignee_user_id IS NULL OR assignee_user_id NOT IN (SELECT id FROM ssl_sys_user WHERE status = 1)`。
5. 自动分派（积压最少）返回 `Long userId`；被指派人姓名快照从查到的 `SysUser.getRealName()` 写入 `xxxRealName` 列。
6. 消息正文、审计 detail 里不得拼账号；只拼真实姓名（`actor.getRealName()` / 列里存的姓名列）。
7. VO/出参：把原来承载账号的字段改成 `xxxUserId(Long)` + `xxxName(String)`；不要输出 username。
   前端下拉的 `value` 用 `user_id`（见 UserSimpleVO / LoginVO）。
8. 不改数据库脚本、不改其它模块的既有业务语义；不做顺手重构。
9. 中文注释保持 UTF-8；不要新增大段说明性文案。

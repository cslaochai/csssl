# csssl 院内证书策略声明（CP/CPS 摘要）与 KMC 豁免声明

> 文件性质：csssl 院内 CA 建设合规声明材料，用于密评预审 / 等保评估 / 内部审计对标的书面依据。
> 对标标准：《GM/T 0034-2014 基于SM2密码算法的证书认证系统密码及其相关安全技术规范》《GM/T 0015-2012 数字证书格式》
> 版本：v1.0　日期：2026-10-27　签发主体：长沙麓康医院信息科（csssl 工程）

---

## 一、KMC（密钥管理中心）豁免声明

**声明：** 本院自建 CA（csssl）**仅签发签名/认证用途数字证书，不签发加密证书，不托管任何加密证书私钥**，因此**不建设独立密钥管理中心（KMC）**，不存在加密证书密钥托管、备份、恢复链路。

**依据与理由：**

| 条款 | 原文要点 | 对本 CA 的适用 |
|---|---|---|
| GM/T 0034 §1 范围 | "本标准适用于指导**第三方认证机构**的数字证书认证系统的建设和检测评估……**非第三方认证机构**的数字证书认证系统的建设、运行及管理，**可参照**本标准" | csssl 属院内非第三方 CA，标准为参照执行 |
| GM/T 0034 §5.1 | "证书认证系统**必须采用双证书**……并建设**双中心**（证书认证中心和密钥管理中心）" | 双证书+双中心面向**第三方持证 CA**；本院不对外发证、不发加密证书，不触及其强制范围 |
| GM/T 0034 §5.2.3.3 | "用于数据加密的密钥对由**密钥管理中心**产生并负责安全管理" | 本院不产生、不管理加密密钥对，签名密钥对由证书持有方自持 |

**签名私钥管理原则（对应标准 §5.2.3.3 签名密钥可由载体产生）：**
1. 医生/机构签名证书：私钥在申请方本地生成（UKey 内生成或软件生成），**私钥不出申请方**，CA 仅持有公钥（RA 公钥签发流程）。
2. CA 侧内部生成的证书私钥：经密钥保险库 **SM4 加密落盘**（store-dir），主密钥独立保管；根 CA 私钥**封存离线**，日常签发由 SUB_CA 承担。
3. **本 CA 不提供**加密证书、加密私钥托管、密钥恢复等 KMC 职能。

**影响说明：** 若未来院内系统确需"加密证书 + 密钥托管"（如跨机构加密传输要求密钥恢复能力），须另行立项建设 KMC 或采购商用 KMC 产品，本声明届时废止并更新。

## 二、证书策略（院内版 CP 摘要）

### 2.1 证书类型与用途

| 模板编码 | 证书类型 | 主体 | 用途 | KeyUsage | EKU | 有效期 |
|---|---|---|---|---|---|---|
| SERVER_COMM | 机构通信证书（SERVER） | 前置机/局端/子系统 | 系统间加密传输、TLS 服务端 | digitalSignature, keyEncipherment | serverAuth | 2 年（730天） |
| DOCTOR_SIGN | 医生签名证书（CLIENT） | 医护人员 | 病历/处方电子签名 | digitalSignature | clientAuth | 1 年（365天） |
| SUB_CA | 二级CA证书（SUB_CA） | 服务签发CA | 证书/CRL 签发 | keyCertSign, cRLSign | — | 2 年（730天） |

- 证书格式遵循 **GM/T 0015**；签名算法 RSA2048（SHA256withRSA）/ SM2（SM3withSM2）。
- 策略 OID：SM2 签名证书采用 **1.2.156.112562.2.2.15**（国密 SM2 签名证书策略 OID）。

### 2.2 证书扩展项（签发时由模板锁定，不允许手工拼装）

- basicConstraints：SUB_CA 置 CA:true(pathLen=1)，终端证书 CA:false。
- keyUsage / extendedKeyUsage：按上表模板锁定。
- certificatePolicies：写入策略 OID。
- subjectKeyIdentifier / authorityKeyIdentifier：签发时自动生成。
- subjectAlternativeName：按申请提交（DNS/IP）。
- cRLDistributionPoints（CDP）：证书内置 CRL 下载地址（publicBaseUrl/ca/public/crl）。
- authorityInfoAccess（AIA）：证书内置 OCSP 地址（publicBaseUrl/ca/public/ocsp）。

### 2.3 签发流程（RA 用户注册，对应 §5.2.2）

1. **提交**：CA 操作员（OPERATOR）录入申请（机构：营业执照+经办人证件；个人：身份证+执业信息）。
2. **审核**：审核员（APPROVER）审核材料与主体身份，**审核人不得为提交人本人**（§10.1g 强制）。
3. **签发**：操作员按模板签发，私钥申请方自持（公钥签发流程）。
4. 全程审计留痕（签名防篡改 + 哈希链）。

### 2.4 证书状态与吊销

| 状态 | 说明 | CRL 表现 | OCSP 表现 |
|---|---|---|---|
| VALID | 有效 | 不出现 | good |
| FROZEN | 挂起（暂停使用，可恢复） | certificateHold | revoked(on-hold) |
| REVOKED | 已吊销（不可逆） | 对应原因码 | revoked |
| EXPIRED | 已过期（自动归档标记） | 不主动发布 | unknown/不回应 |

- **吊销时限承诺**：受理吊销申请并审核无误后 **24 小时内**发布至 CRL（对齐 BJCA/浙江CA 行业标准）。
- 吊销原因：KEY_COMPROMISE / CA_COMPROMISE / AFFILIATION_CHANGED / SUPERSEDED / CESSATION_OF_OPERATION / CERTIFICATE_HOLD / PRIVILEGE_WITHDRAWN / UNSPECIFIED。
- 挂起适用：人员离职待定、设备临时停用、司法冻结请求（国家电子政务外网证书策略 4.10.1 情形）。

### 2.5 归档与留存

- 证书签发记录与证书文件：**有效期届满后留存 ≥10 年**（对齐 GM/T 0034 §9.2.2 密钥保存期 >10 年）。
- 审计日志：**留存 ≥5 年**（对齐等保三级审计要求），只增不改，逐条 SM3withSM2 签名 + 哈希链，可在线验签。

### 2.6 时间戳

- 提供院内 TSA 服务（SM3withSM2 令牌），业务系统病历/处方签名可同步取权威时间戳（WS/T 847—2024 医学电子文档数字签名技术标准方向）。

## 三、安全与分权（对应 §8.1.3 / §10.1）

| 角色 | 职责 | 关键权限 |
|---|---|---|
| ADMIN 系统管理员 | 用户/角色管理、根CA维护 | 建号、封存/解封根私钥、模板增删改 |
| OPERATOR CA操作员 | 申请录入、签发、吊销/挂起/更新 | 与审核分离 |
| APPROVER 审核员 | 审核申请单 | 不得与录入员同一人 |
| AUDITOR 审计员 | 审计日志查询、验签 | 只读，不可签发/审核 |

- 管理员口令：BCrypt 存储，登录传输 SM2 口令加密（院内双因素增强为 UKey+口令属 P2 计划）。
- 根密钥：SM4 加密落盘 + 封存离线；解封须系统管理员操作并全程审计。

## 四、合规红线声明

1. csssl 为**院内自用** CA，**不向社会公众提供电子认证服务**（《电子签名法》第17/18条持证要求不适用）；如对外开放发证，须另行取得工信部电子认证服务许可。
2. 证书/签名效力认定依据《电子签名法》第13条"可靠电子签名"四要件，院内制度配合（签署人身份、意愿、数据电文完整性、可信时间戳）。
3. 涉及商用密码应用的关键信息基础设施/重要系统，按《商用密码管理条例》与《商用密码应用安全性评估管理办法》开展密评；本声明作为"设备与计算、应用与数据"层 PKI 部分的书面材料。

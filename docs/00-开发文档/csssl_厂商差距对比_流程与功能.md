# csssl 与国内 CA 厂商差距对比：流程 × 功能全景

> **定位**：csssl 是院内非第三方 CA（为 HIS 生态提供信任根与证书签发，不对外发证），本文回答一个问题——**与国内厂商相比，csssl 在"流程"和"功能"两个维度还差哪些**。
> **对比对象**：
> - 持证 CA 运营商（5 家）：CFCA（中金金融认证中心）、北京 CA（数字认证 BJCA）、上海 CA（SHECA）、GDCA（数安时代）、浙江 CA（ZJCA）
> - 商用密码 PKI 产品厂商（6 家）：三未信安、吉大正元、电科网安（卫士通）、格尔软件、数字认证、信安世纪
> **依据材料**：
> - `csmig\施行手册\CA厂商调研\GM_T0034厂商对照\` 三份调研（标准核验与通行做法 / 持证CA机构证据 5 家×8 项 / 商密厂商证据，2026-10-27，来源逐条标注）
> - `csssl\施行手册\docs\CA厂商调研\` 三份调研（医疗医嘱行业 / 对比分析与厂商 / 政策机制与CA，2026-10-27）
> - `csssl\README.md` 代码现状（截至 2026-10-28，路线 A 多机构域 + 路线 B 安全整改已交付，`smoke-route-a.cjs` 24/24、`smoke-route-b.cjs` 14/14）
> - `csssl\docs\csssl_CA厂商差距分析与建设规划.md` v1.0（对标 GM/T 0034 八项强制功能的建设规划，本篇不重复其标准条款逐条论证）
> **差距标尺**：✅ 已追平厂商（或院内场景已闭环）／ ⚠️ 有基础、缺配套 ／ ❌ 缺失

## 0. 一页结论

**一句话**：csssl 的**软件能力面已追平厂商的"CA 核心 + 合规基线"**（签发/吊销/OCSP+CRL/生命周期/模板/六类角色/门限分持/审计防篡改/TSA/多机构域全部交付），剩余差距不在"软件功能有没有"，而集中在五类：

| 差距类别 | 具体项 | 性质 |
|---|---|---|
| ① 硬件密码基础设施 | 服务器密码机/HSM（GM/T 0018，"密钥不落地"）、国密 UKey 发证（GM/T 0016） | ❌ 厂商标配，需采购 |
| ② 标准协议与自动化 | SCEP/CMP 自动注册、LDAP 目录服务、批量注册/审核/签发、REST/SDK 之外的标准接口 | ❌ 设备证书上量前的刚需 |
| ③ 流程与制度配套 | 多级审核、自动审核、权威身份库（医师执业注册库）核验、远程 RA 分节点、用户自助服务门户、双人复核制度化 | ⚠️ 半代码半制度 |
| ④ 托管与恢复链路 | 双证书（签名+加密）+ KMC 加密私钥托管/恢复/司法恢复 | ❌ 已书面豁免（仅第三方持证 CA 强制），能力仍缺 |
| ⑤ 行业化增值形态 | 移动 CA（手机 APP 证书、密钥分割）、云签名、电子签章/OFD 版式归档、事件型证书（患者签名） | ❌ 医院无纸化深水区的能力，厂商在医疗线的主战场 |

合规材料面（KMC 豁免声明 + 院内 CP 摘要）已备齐；管理后台口令修改页为 README 在册 TODO 的小项。

## 1. 对比口径（先读）

| 项目 | 说明 |
|---|---|
| csssl 定位 | 院内非第三方 CA：GM/T 0034 §1 明确"非第三方认证机构……可参照本标准"，csssl 为**参照执行**；院内自用不触《电子签名法》第 17/18 条持证要求，**但不可对外商用发证** |
| 为什么不直接买厂商产品 | 厂商整套 CA+RA+KMC+HSM+UKey 属商用密码产品体系（百万级容量、三区分离、密码机），投入与院内规模不匹配；csssl 以"院内可用 + 可过密评预审"为标尺，不追求运营级容量 |
| 对比的三把尺子 | ①院内场景可用 ②密评/等保预审能过 ③对标厂商功能完整度——差距结论按此三把尺子给出，不按"厂商有而我没有"一刀切 |
| 厂商格局背景 | 全国持证 CA 机构 55 家，证书签发量前 5 名合计占全国 93.2%（2025 年运行数据）——头部高度集中，其 CPS/产品页是"厂商通行做法"的可靠来源 |

## 2. 流程对比：一张证书从申请到归档

### 2.1 厂商标准发证流程（持证 CA 通行版）

以 CFCA / BJCA / 上海 CA / GDCA / 浙江 CA 公开 CPS 与产品页归纳（来源见 §7）：

```
[用户侧]                        [RA 侧]                      [CA/KMC 侧]
申请提出 ──► RA 受理/录入 ──► 身份审核（面签/资料/权威库） ──► CA 签发
  │             │                    │                        │
在线自助 /      录入员（与审核员       机构：营业执照+经办人       SUB_CA 在线签发
柜台面签 /      分离）              个人：身份证件+面签          根 CA 物理离线
批量受理                           医护：对接医师执业注册库      KMC 生成加密密钥对
                                                              （数字信封下发）
                                                                  │
部署使用 ◄── 证书交付 ◄── 介质制作/灌装 ◄─────────────────────────┘
  │         （邮寄/面对面/   （UKey 内生成签名密钥对，
  │           安全通道/        私钥不出介质；一键制证）
  │           空UKey自助下载）
  ▼
TLS/mTLS、电子签名（+权威时间源时间戳，签名同时打戳）
  │
状态查询（CRL 8h/24h 发布 + OCSP 7×24 三态）
  │
到期前更新（BJCA：有效期<90 天可在线更新顺延）／挂起-解挂（certificateHold）／吊销（24h 内生效）
  │
归档（证书数据留存 10 年、审计留存 ≥5 年）
```

### 2.2 逐环节对照表

| # | 流程环节 | 厂商通行做法 | csssl 现状（2026-10-28） | 差距 |
|---|---|---|---|---|
| 1 | 申请提出 | 三通道：RA 柜台面签、在线自助平台、批量受理（CFCA 在线平台"资料填报→审核→支付→制作→发货"全流程；政务 CA 书面申请表 5 类细分） | 管理后台由 OPERATOR 录入（机构/个人），单一通道 | ❌ 无用户自助申请门户、无批量受理 |
| 2 | 身份审核 | 双岗分离（GDCA"录入员/审核员"分设；标准 §10.1g 强制）+ 多级审核（政务 CA"录入→初审→复审"）+ 人工/自动双轨（§8.1.1c）+ **权威库核验**（上海 CA 整合医师联网注册库作为 RA 身份底座；机构审营业执照+授权委托书） | 单级人工审核，**审核人≠录入人已强制**（达标）；模板锁定扩展项防越权 | ⚠️ 缺多级审核、自动审核；缺医师执业注册库等权威身份核验底座（影响证书法律证据力） |
| 3 | 密钥生成 / 介质制作 | 签名密钥对在 UKey 内生成（私钥不出介质，WS/T 847—2024 硬性要求）；RA 一键制证（CFCA 制证平台：插 UKey→读序列号→一键制证）；加密密钥对由 KMC 生成、SM2 数字信封下发 | 三入口覆盖：在线签发（CA 侧密钥 SM4 加密落盘）/ CSR 签发 / **公钥签发（申请方自持私钥，私钥不出申请方）**；PKCS#12 软件证书导出已交付 | ⚠️ 公钥签发流程在语义上对应"私钥不出申请方"；**缺 UKey 灌装制证环节**（GM/T 0016 保护结构），软件证书链路已闭环 |
| 4 | 证书签发 | 根 CA 物理离线 + SUB_CA 在线签发；三区分离部署（卫士通典型架构：核心/管理/服务区） | 根私钥封存离线（可解封）或 Shamir(3,5) 门限分持（份额为唯一持久形态）；SUB_CA 在线签发；到期自动轮换 | ✅ 逻辑追平（差异在"软件离线"vs"物理隔离+密码机"，见 §4.2） |
| 5 | 证书交付 | 邮寄/面对面/安全通道；空 UKey 用户自助下载；证书自动跳转导入 UKey（GDCA 灌装通知） | 管理端下载 cert.pem（叶子+SUB_CA 完整链）/ p12 打包导出 | ⚠️ 缺面向申请人的自助下载与交付通知 |
| 6 | 部署使用 | 厂商提供客户端工具/中间件（BJCA 证书助手、ZJCA 客户端、GDCA 换 Key 补发） | 证书链下载免手工拼接，TLS/mTLS 双向认证直用；HIS/csmig 已对接实测 | ✅ 院内场景已闭环（厂商客户端工具服务于海量公众用户，院内无此规模需求） |
| 7 | 状态查询 | CRL 发布周期 8h（GDCA 部分根族）/24h（BJCA/ZJCA），nextUpdate≤7–10 天；OCSP 7×24 三态（RFC 6960/2560）、响应签名、Nonce 防重放；增量/分块 CRL（格尔） | CRL 全量+**增量 dCRL**（RFC 5280 §5.2.4，DeltaCRLIndicator）+内容指纹判重+每日定时发布；OCSP 三态 POST+GET 双通道、SUB_CA 签名、nextUpdate 可配；CDP/AIA 内置 | ✅ 追平且部分超出行业 CPS 常规（指纹判重防刷号、增量 CRL） |
| 8 | 更新 / 挂起 | 到期前更新（BJCA：有效期<90 天或过期≤1 年可在线更新顺延 1 年）；挂起/解除挂起以 CRL certificateHold + OCSP on-hold 体现（§12.6/12.7） | renew（同公钥重签+旧证 SUPERSEDED）/ rekey（换密钥重签）/ suspend / unsuspend 全部交付（GM/T 0034 §12 对齐） | ✅ |
| 9 | 吊销 | 吊销申请审核后 24h 内生效并发布 CRL（BJCA/GDCA/浙江 CA 承诺） | 吊销+每日定时 CRL 发布（指纹判重） | ✅（发布节奏与厂商 24h 口径同级） |
| 10 | 归档 | 证书失效后数据留存 10 年（四川 CA CPS；标准 §9.2.2 密钥保存期>10 年）；审计留存 ≥5 年（BJCA） | 审计归档导出 CSV（UTF-8 BOM）+ 报告 SM2 签名，留存 ≥5 年材料；证书过期归档状态机 | ✅（**自动归档策略可再制度化**：年限写入口径文件即可） |
| 11 | 全流程自动化 | 设备证书 SCEP 自动注册（GM/T 0089—2020）、CMP/MQTT 协议、批量注册/批量审核/批量签发/批量废除（格尔大客户版） | 全部人工界面操作，HTTP JSON API | ❌ 前置机/医疗设备证书上量前的刚需 |
| 12 | RA 网络分布 | 远程 RA 分节点（VPN/专线，标准附录 A：C/S、B/S、远程 RA 三种连接）、多级 RA | 单点部署，管理端即 RA | ❌ 多院区/医共体场景才需要（P3） |

### 2.3 流程维度结论

- **主干流程（申请→审核→签发→使用→查询→变更→吊销→归档）csssl 全部贯通**，且审核分离、状态机、发布时效均达厂商 CPS 口径。
- 流程短板集中在**"入口侧"与"介质侧"**：没有自助申请/下载门户（申请人依赖管理员代办）、没有 UKey 制证灌装环节、没有批量与自动注册。院内规模小时代办模式可接受；设备证书（前置机、终端、 мед防设备）上量后，**SCEP + 批量签发是第一个必须补的流程项**。
- 法律证据力层面，厂商靠"面签/权威库核验"背书身份真实性；csssl 的医护身份核验目前靠院内人事管理，**若病历签名要走司法/卫健检查口径，对接医师执业注册库（或省级卫生 CA 互认）是流程上最值得补的一块**。

### 3.3 协议、自动化与自助服务

| 项 | 厂商做法 | csssl 现状 | 差距 |
|---|---|---|---|
| SCEP（GM/T 0089） | 设备证书自动注册 | 无 | ❌ 前置机/设备证书上量前必补 |
| CMP / MQTT | 标准注册协议（BJCA 支持 MQTT/CMP） | 无 | ❌ 同上（优先级低于 SCEP） |
| LDAP 目录服务 | 证书/CRL 实时发布到目录（三未/BJCA/CFCA） | HTTP 端点发布（root/subca/crl/ocsp） | ⚠️ 院内 HTTP 够用；跨系统大规模依赖方时补 |
| 批量操作 | 批量注册/审核/签发/废除（格尔） | 单笔操作 | ❌ 批量签发接口工作量小，建议补 |
| 自助服务门户 | 用户在线申请/下载/更新/解锁/吊销 | 无（管理端代办） | ⚠️ 院内可接受；医共体对外服务时必补 |
| 移动 CA / 云签名 | 手机 APP 证书替代 UKey（上海 CA 胸科/瑞金案例）；移动私钥**密钥分割、介质+服务端联合签名**（WS/T 847—2024 强制） | 无 | ❌ 医护移动查房/移动签名场景的行业主流形态 |

### 3.4 行业化能力（医疗线——厂商的主战场）

| 项 | 厂商做法（医疗） | csssl 现状 | 差距 |
|---|---|---|---|
| 医护身份权威核验 | 上海 CA 以医师联网注册库为 RA 身份底座；卫生行业 CA 两级体系（卫办综发〔2010〕74 号）要求互信互认 | 院内人事管理背书 | ❌ 影响证书法律证据力（司法/卫健检查口径） |
| 电子签章与版式归档 | 签章中间件（金格 iSignature）+ OFD 版式 + 电子病案"收管存用"全生命周期；归档时机构证书再签一次+时间戳 | TSA 已对接；归档二次签名/OFD 未做 | ❌ 属 HIS/EMR 应用层能力，建议按 WS/T 847—2024 归档条款另行立项（边界在 cslk 侧，不在 CA 本体） |
| 患者（服务对象）签名 | 事件型证书：组合鉴别（人脸/指纹/短信）、私钥当次销毁（WS/T 847—2024） | 无 | ❌ 知情同意书等场景的远期能力 |

## 4. 差距归因：为什么是这几块（而不是更多）

1. **csssl 已追平的部分，本质是"软件可表达的能力"**——状态机、协议报文（OCSP/CRL）、角色模型、审计链、模板、多域隔离，这些不依赖硬件，两天调研后的两波改造（路线 A/B）已把 GM/T 0034 的软件面要求全部落掉。
2. **剩余差距几乎都卡在"硬件+介质+权威背书"三件事上**——这正是持证 CA 与商密厂商的护城河：密码机（资产）、UKey 发证链路（介质+SDK+目录认证产品）、医师注册库/面签（权威身份底座）。这三件不是纯代码问题，分别对应**采购、SDK 对接立项、跨机构协作**。
3. **两把尺子要分清**：按"院内可用"尺子，除 UKey/HSM 外几乎无硬差距；按"过密评/等保三级"尺子，**HSM（密评对密钥存储的实务要求）+管理员双因素**是两个确定性检查点。
